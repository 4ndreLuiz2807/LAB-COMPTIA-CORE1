Não confunda: MX indica destino de recebimento de e-mail; SPF, DKIM e DMARC auxiliam na autenticação e na política de tratamento de mensagens. Um registro DNS correto não substitui um serviço de e-mail funcionando.

2. DHCP: atribuição automática

DORA = Discover → Offer → Request → Acknowledge. O cliente procura um servidor, recebe uma oferta, solicita o endereço e recebe confirmação. O escopo DHCP contém faixa de IP, máscara, duração do lease e opções como gateway e DNS.

Reserva DHCP: vincula um IP a um cliente identificado normalmente pelo MAC, útil para impressoras. IP estático: configurado diretamente no dispositivo; não depende de obter lease do servidor.

3. VLAN: segmentação lógica

Uma VLAN separa domínios de broadcast em um switch gerenciável. Dispositivos em VLANs distintas geralmente precisam de um roteador ou switch camada 3 para trocar tráfego. VLAN não é sinônimo de firewall: permissões de acesso dependem de regras de roteamento/segurança.

4. VPN: comunicação protegida

Client-to-site: notebook remoto acessa a rede corporativa por um túnel. Site-to-site: duas redes de unidades diferentes se conectam por túnel entre gateways. VPN e VLAN resolvem problemas diferentes: a primeira cria conectividade protegida entre pontos; a segunda segmenta redes locais.

Revisão espaçada de portas: SMB = TCP 445 (pastas/impressoras); SMTP = TCP 25 (transporte entre servidores de e-mail); LDAP = TCP/UDP 389 (consulta de diretório). Para clientes de e-mail, a submissão autenticada costuma usar TCP 587. LDAP não deve ser confundido com Kerberos (porta 88), usado frequentemente na autenticação de domínio.

🧪 Laboratório Windows — 20 minutos

Ambiente: PowerShell no Windows 10/11. Execute somente consultas, sem modificar DNS, DHCP ou firewall corporativo.

Etapa 1 — Verificar a configuração atual

ipconfig /all

Anote IPv4, máscara, gateway, servidor DHCP e servidores DNS. Identifique se o endereço parece ter sido atribuído automaticamente.

Etapa 2 — Comparar tipos de registro DNS

Resolve-DnsName microsoft.com -Type A
Resolve-DnsName microsoft.com -Type AAAA
Resolve-DnsName microsoft.com -Type MX

Compare o tipo de resposta. Alguns domínios podem não publicar determinado tipo de registro; isso não significa necessariamente que seu DNS esteja quebrado.

Etapa 3 — Inspecionar servidores DNS e rotas

Get-DnsClientServerAddress
Get-NetRoute -DestinationPrefix '0.0.0.0/0'

Qual gateway é usado para tráfego IPv4 fora da sub-rede? Qual DNS está configurado na interface?

Etapa 4 — Testar uma porta de compartilhamento (somente em servidor autorizado)

Test-NetConnection -ComputerName SERVIDOR01 -Port 445

Substitua SERVIDOR01 pelo nome de um servidor que você tenha autorização para testar. TcpTestSucceeded: True comprova estabelecimento TCP, não que você possua permissão para abrir a pasta.
